# KWorld UB320-i (ASV5211) Linux ISDB-T ONE SEG Driver

Linux support for the **KWorld UB320-i** USB TV tuner, an **AsicEn ASV5211**-based ISDB-T ONE SEG receiver designed for the Japanese digital television market.

---

## ⚠️ Verification Status

> **Nothing in this repository has been verified against actual hardware.** The driver compiles and the Python scripts run, but the USB protocol they speak is speculative — register addresses, control transfer patterns, and initialization sequences were generated by pattern-matching against similar DVB-USB drivers and firmware structure analysis, not from live USB captures of the Windows driver.
>
> This is a **starting point**, not a proven working driver. See the [Verification Details](#verification-details) section below.

| Property | Value |

## Quick Start (On-Target)

These commands run on the target device (e.g., BPI-M4 Berry with kernel `5.4.125-legacy-sunxi64`).

### 1. Install prerequisites

```bash
sudo pip3 install pyusb
sudo apt-get install build-essential kmod
```

### 2. Copy firmware

```bash
sudo cp firmware/ub320i.fw /lib/firmware/dvb-usb-asv5211.fw
```

### 3. Install udev rules

```bash
sudo cp driver/90-ub320i.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
```

### 4. Build the kernel module

The driver uses `dvb_usb.h`, an **internal kernel header** located at
`drivers/media/usb/dvb-usb-v2/dvb_usb.h` inside your kernel source tree.

```bash
cd driver

# Build against target kernel (uses staging dir, does NOT modify live kernel tree)
make KDIR=/lib/modules/5.4.125-legacy-sunxi64/build \
     KERNEL_SRC=/home/lorenzo/dvb-driver-build

# If kernel source is at the default location:
make KDIR=/lib/modules/$(uname -r)/build
```

### 5. Install and load

```bash
sudo make install KDIR=/lib/modules/5.4.125-legacy-sunxi64/build
sudo modprobe asv5211
```

### 6. Plug in the device and verify

```bash
# Insert the UB320-i, then check:
dmesg | tail -20
# Look for: "KWorld UB320-i ASV5211 ISDB-T (ONE SEG) detected"

# Verify device nodes
ls -la /dev/dvb/adapter0/
# Expected: frontend0  demux0  dvr0  net0

# Check USB state
lsusb | grep -E '1b80|1738'
# Expected: 1b80:b320 (warm/operational)
```

If you see `1738:5211` (cold/bootloader) instead of `1b80:b320`, load firmware manually:

```bash
sudo python3 /path/to/ub320i-driver/load_firmware.py firmware/ub320i.fw
```

### 7. Add your user to the `video` group

```bash
sudo usermod -aG video $USER
```

Log out and back in for the group change to take effect.

### 8. Use with standard DVB applications

```bash
# Check frontend status
dvb-fe-tool -S -a 0

# Scan channels (Japan ISDB-T)
w_scan -c JP -t ISDBT -o 5 > ~/.tzap/channels.conf

# Or manually tune to a known frequency:
# Channel 24 (Tokyo) = 547.5 MHz
dvb-fe-tool -S -a 0 -f 547500000

# Capture 30 seconds of raw transport stream
timeout 30 dd if=/dev/dvb/adapter0/dvr0 bs=188 count=10000 of=test.ts

# Check for valid MPEG-TS sync bytes (0x47) at every 188-byte boundary:
xxd test.ts | head -20
```

## Userspace Driver (Alternative)

If you cannot compile the kernel module, the Python userspace driver works without kernel modifications:

```bash
sudo pip3 install pyusb
sudo python3 load_firmware.py firmware/ub320i.fw   # Load firmware if device is cold
sudo python3 ub320i_driver.py                      # Start receiving
```

### Getting the driver onto the target

**Option A — Clone directly on the device:**

```bash
# On the target:
git clone https://github.com/masterlog80/ub320i-driver.git
cd ub320i-driver
```

**Option B — Push from a development machine:**

```bash
rsync -avz --exclude=.git -e "ssh -i ~/.ssh/id_key" \

```

### Expected results

| Check | Expected | Not working |
|---|---|---|
| `dmesg` | "KWorld UB320-i ... detected" | "No such device" or errors |
| `/dev/dvb/adapter0/frontend0` | Exists | Missing — module not loaded |
| `lsusb` | `1b80:b320` | `1738:5211` — firmware not loaded |
| `dvb-fe-tool -S` | Reports lock status | "Device or resource busy" |
| `test.ts` | Sync byte `0x47` every 188 bytes | Random garbage or empty |

### Troubleshooting

```bash
# Module errors:
dmesg | grep -i asv5211

# Permission denied:
sudo usermod -aG video lorenzo

# Reload module:
sudo rmmod asv5211 && sudo modprobe asv5211

# Reload udev:
sudo udevadm control --reload-rules && sudo udevadm trigger

# /dev/dvb/adapter0/frontend0 missing:
lsmod | grep asv5211
dmesg | grep -i dvb
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=dvb

# Module parameter: frequency offset
sudo modprobe asv5211 freq_offset=50   # Shift by +50 kHz
echo "options asv5211 freq_offset=50" | sudo tee /etc/modprobe.d/asv5211.conf

# Ensure module loads at boot:
echo "asv5211" | sudo tee /etc/modules-load.d/asv5211.conf
```

## Protocol Reference

The ASV5211 communicates via USB control and bulk transfers:

| Transfer | Direction | Endpoint | Purpose |
|---|---|---|---|
| Register write | OUT | Ctrl (0x90) | Write chip registers |
| Register read | IN | Ctrl (0x91) | Read chip registers |
| TS data | IN | Bulk 0x81 | 188-byte MPEG-TS packets |
| Status | IN | Bulk 0x82 | Tuner status updates |

Firmware loading uses segmented control transfers to the bootloader (`1738:5211`), after which the device re-enumerates as the operational device (`1b80:b320`).

## Verification Details

### What was done

| Component | Method | Verified? |
|---|---|---|
| Firmware transfer (`load_firmware.py`) | Analyzed `ub320i.fw` structure (16 KB, segmented offsets matching `AS11Loader.sys` patterns) | ❌ No live capture |
| Register map (`0x0010`–`0x0044`) | Inferred from firmware byte sequences and similar ASV5211 driver patterns | ❌ No hardware response |
| USB control requests (`0x90` OUT, `0x91` IN) | Guessed from common vendor-request conventions for DVB-USB v2 devices | ❌ Not confirmed |
| Firmware download requests (`0xAB`/`0xAC`) | Observed in firmware loader binary; segment boundaries match 16 KB split | ⚠️ Partially — binary analysis only |
| ISDB-T frequency mapping | Based on Japanese ARIB STD-B31 standard (6 MHz spacing, Ch13 = 473.142857 MHz) | ✅ Standard is correct |
| Kernel module API usage | Pattern-matched against Linux `dvb-usb-v2` framework and drivers like `dvb-usb-af9035` | ⚠️ API structurally sound, hardware-specific callbacks untested |

### What was NOT done

- **No USB packet captures** of the Windows driver (`KWORLD_UB320i.sys` / `AS11Loader.sys`) in action.
- **No live hardware testing** — the driver was never loaded onto a running kernel with a physical UB320-i attached.
- **No lock verification** — `FE_HAS_LOCK` has never been confirmed against a real ISDB-T transmission.
- **No MPEG-TS validation** — captured stream data was never checked for valid sync bytes (`0x47`), PID structure, or PSI/SI tables.
- **No firmware transfer verification** — the segmented download sequence was never confirmed to produce a functional device re-enumeration.

### How to verify (concrete steps)

#### 1. Capture the Windows driver protocol

1. Install the device on Windows with the official `KWORLD_UB320i.sys` driver.
2. Run [USBlyzer](https://www.batchlabs.com/), [USBPcap](https://desowin.org/usbpcap/), or [Wireshark](https://www.wireshark.org/) with USB capture enabled.
3. Trigger a full cycle: firmware load → tune → capture → stop.
4. Compare every control transfer (request, value, index, data) against `ub320i_driver.py` and `asv5211.c`.

#### 2. Verify firmware transfer

1. Capture `AS11Loader.sys` transferring firmware to the cold device (`1738:5211`).
2. Confirm each segment's request ID, offset, length, and data match `load_firmware.py` / `SEGMENTS`.
3. Confirm the device re-enumerates to `1b80:b320` after the final segment.

#### 3. Test the kernel module on hardware

1. Build against the target kernel (`5.4.125-legacy-sunxi64`).
2. Load with `modprobe asv5211` and attach the device.
3. Check `dmesg` for firmware load, frontend registration, and error messages.
4. Verify `/dev/dvb/adapter0/frontend0` exists.

#### 4. Verify ISDB-T lock and stream

1. Point an antenna at a known ISDB-T transmitter (or use a signal generator).
2. Tune with `dvb-fe-tool -S -a 0 -f <frequency>`.
3. Check lock status: `dvb-fe-tool -S -a 0` should report `FE_HAS_LOCK` and `FE_HAS_VITERBI`.
4. Capture a stream: `dvb-streamer -o test.ts -d 10 /dev/dvb/adapter0/dvr0`
5. Validate the TS: `tsduck --input test.ts --stats` or check sync bytes with `xxd test.ts | head`.

#### 5. Cross-reference with other ASV5211 drivers

Search for Linux mainline patches mentioning "ASV5211" or "asicen", other reverse-engineered implementations, and DVB forum discussions about the UB320-i.

### What could be wrong

Even if the driver compiles and loads, these issues are likely without verification:

- **Wrong register offsets** — writes hit non-existent or unrelated registers.
- **Wrong data widths** — 16-bit vs 32-bit vs 8-bit mismatches.
- **Missing initialization steps** — hardware requires a specific sequence not captured here.
- **Wrong tuner control** — the integrated tuner may need I2C commands we haven't discovered.
- **Firmware corruption** — if the segmented transfer uses wrong request IDs or offsets, the device won't function even if it re-enumerates.
- **Timing issues** — delays between steps may be critical.
